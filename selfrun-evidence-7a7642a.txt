Two corrections worth recording
-------------------------------
1. The first image built from 1ed0336 failed collection with "Form data
   requires python-multipart". requirements.txt never listed it; the host venv
   happened to have it, so 370 tests passed in the source tree while every
   form route would have returned 500 in the container. Found only by running
   the suite inside the image. Fixed in 7a7642a.
2. A token-free export probe that hit a non-existent /export path appeared to
   pass, because a 404 error body contains no "tokens" key. The real routes are
   /_test/export and /_test/import. The export numbers above come from the real
   routes. The earlier W7 claim that a removed user gets 401 was NOT reproduced
   by this probe - an import that drops a user is refused 422 instead - so that
   claim is not restated here as verified.

G5 did not pass before 066bb0a. A deprovisioning import that still carries the
removed user's token has to import and log them out (G3), so that token was
dropped rather than refused - which also silently accepted a token naming a
handle that had never existed. 066bb0a separates the two: a handle this import
removes is dropped, a handle never present is a 422. Both branches are pinned in
one test, because a payload without requests/activity/idempotency is a bare
fixture that never reaches the tokens handling and would pass for the wrong
reason - which is exactly what my first version of that test did.
